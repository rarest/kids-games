## Context

参见 `proposal.md` 的 Why。当前 `joystick-controls.js` 只通过 `abs(dx) >= abs(dy)` 选择一个主轴，主轴不变时忽略另一个轴的出现；控制器每 100 毫秒直接把该方向交给 `main.js`，而 `main.js` 直到调用 `engine.move()` 后才知道该格是否可通行。因此斜推中的转弯信息在控制层被永久丢弃，控制器也无法区分“尚未到路口”与“该方向永远是墙”。

迷宫移动是离散四邻接格，不允许斜向跨格。虚拟摇杆需要服务手机、平板、鼠标和触控笔；炸药与钩子必须继续是一次性方向操作。关卡、存档和碰撞规则不能变化。

## Goals / Non-Goals

**Goals:**

- 把指针向量稳定转换为最多两个相邻的四向意图，并在路口按真实可通行格解析方向。
- 允许玩家在抵达路口前预输入垂直转向，在第一个开放格可靠转弯。
- 保留碰壁反馈、安全取消、多设备归一化以及工具单次方向语义。
- 让输入解析和地图转向策略可分别进行确定性单元测试。

**Non-Goals:**

- 不提供自动寻路、路线提示、自动避障或斜向移动。
- 不修改地图生成、墙体几何、摄像机或存档。
- 不改变键盘和无障碍四向按钮的精确单步行为。

## Decisions

### 1. 分离“指针意图”与“格子导航”

底层摇杆控制器把相对中心的向量归一化为主方向和可选的垂直次方向。主方向使用迟滞：新轴只有明显超过当前主轴后才取得主导权；两个轴都达到有效幅度时仍保留次方向。主方向与次方向的顺序属于输入语义，玩家明确交换两者时会重新武装下一次转向，不会因为方向集合相同而被误判为旧输入。死区和次轴门槛按摇杆半径比例计算，避免固定像素在手机和平板上产生不同手感。

路口导航器接收 `{primary, secondary}`、最近一次成功行进方向和当前格可通行查询。它只输出一个四方向动作，不直接操作 DOM 或地图。相比继续让单一 `directionForJoystick()` 决定全部行为，这一边界保留了玩家的完整输入；相比八方向移动，它不会破坏四邻接碰撞规则。

### 2. 仅对玩家明确表达的垂直方向进行预转向

当输入同时包含最近行进方向和一个垂直方向时，导航器把垂直方向记为待转向方向，并记录短时有效期。每个移动节拍先检查待转向方向是否开放：开放则立即转弯；未开放但当前行进方向仍开放则继续前进。若主方向受阻而次方向开放，则选择次方向。仅输入一个受阻方向时仍产生原有碰壁反馈，不会自行选择其他通路。

待转向只在新的有序双轴意图出现时武装一次，连续移动节拍不会延长其有效期；玩家持续表达同一输入但超过 400 毫秒后，旧转向不会在更远路口执行。待转向还会在死区、松手、取消、失焦或隐藏时清空。选择工具时绕过导航器，并在同一指针手势首次提交方向后锁定该手势；即使工具成功后选择状态被清除，旋转仍不能追加移动。相比只降低连续移动速度，该策略能够可靠命中一格宽路口；相比自动选择所有可通行方向，它保留玩家选路权。

### 3. 可通行性采用只读物理格查询

引擎提供不修改运行状态的相邻物理格查询，用于区分墙壁和开放地面。出口即使钥匙不足也视为物理可达，实际 `move()` 仍负责产生门锁事件；这样不会吞掉门锁提示。待转向只有在真实人物坐标变化后才标记为已消费，锁门或碰壁会保留该转向直至到期，不允许人物沿另一方向越过目标分支。成功移动后导航器更新行进方向，碰壁、门锁和工具事件不伪造新的行进方向。

主控制器让普通摇杆输入经过导航器，再调用现有 `applyDirection()`；该函数返回真实移动结果供导航器确认。键盘、无障碍按钮和工具继续直接调用原有方向路径。

### 4. 以确定性路口夹具和真实设备事件双层验证

单元测试用手工校验的 L、T、十字、S 弯和死路格子夹具断言实际人物坐标，覆盖主轴临界抖动、预转向、备用方向、缓存到期和取消。浏览器测试在手机与平板视口发送真实 pointer 事件，验证相同比例输入产生一致方向、释放后无残留移动，并继续检查页面无选区和画布无遮挡。

主题渲染压力测试与本次输入行为无耦合；其既有环境时序波动单独记录，不通过放宽路口断言掩盖。

### 5. 触控尺寸和重复节奏服务精准单步

手机竖屏摇杆的可见直径提升到约 84 像素，平板可提升到 90 像素；矮屏竖屏不得再缩到 52 像素。摇杆所在卡片同时作为有效触控表面，指针按下位置按固定摇杆中心计算，指针捕获继续保证手指略微滑出后仍可控制。极矮横屏保留紧凑布局，但维持不低于 68 像素的直径。

控制器按下有效方向后立即发出一格移动，然后等待 240 毫秒才开始连续移动；连续移动初期每 165 毫秒一格，持续按住 1 秒后切换为每 125 毫秒一格。方向改变会立即执行新方向并重新进入精准阶段；进入死区、松手或取消会清空所有计时器。工具手势仍只提交一次，不进入重复节奏。

相比统一降低速度，分段节奏允许轻触产生可靠单步，同时不会让长走廊永久变慢；相比自动沿走廊行进，它不引入自主移动。响应式浏览器测试读取实际边界尺寸，并以真实 pointer 事件验证轻触、长按、加速与释放停止。

## Risks / Trade-offs

- [转向缓存过长可能让过时意图在后续路口执行] → 使用短有效期，并在方向改变、死区、释放和任何取消条件下清除或替换。
- [主轴临界迟滞过强会让玩家感觉转向不灵敏] → 迟滞只决定主方向稳定性，明确达到门槛的次轴仍可作为预转向，手机和平板使用同一归一化比例。
- [可通行查询与实际移动规则漂移] → 查询只负责物理墙判断，最终动作仍由现有 `move()` 执行；集成测试同时验证查询结果和真实人物坐标。
- [连续碰壁重复播放声音] → 保留首次碰壁反馈，并由既有音频节流限制密集反馈；不以静默失败掩盖错误方向。
- [扩大控件会压缩迷宫画布] → 优先收起辅助说明文字并在现有底部控制区内重排，不覆盖画布；极矮横屏使用 68 像素紧凑尺寸。
- [分段速度造成节奏突变] → 只设置一次温和加速，方向改变后回到精准阶段，并用确定性假计时器验证边界。

## Migration Plan

1. 先提交失败的输入解析和真实格子路口测试，确认旧控制器会越过路口或丢失次轴。
2. 实现归一化意图、迟滞和路径感知导航器，再接入普通摇杆移动与安全取消路径。
3. 更新统一资源版本，执行单元、手机、平板和完整浏览器回归。
4. 通过现有 PR 和自动部署流程发布；线上异常时回滚该发布提交即可，不涉及存档或服务器数据迁移。
