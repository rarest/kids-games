## Context

动机见 proposal.md。项目是静态 ES 模块游戏厅，最新主线已含3D赛车及锁定的 Three.js 0.186.1；部署发布打包资产。新游戏独立在 `parkour/`，不修改已有游戏逻辑，不携带其他工作树的未发布改动。用户确认自由移动模式 B，且此前已要求自动实施和完成后自行部署；设计、实现、验证连续推进。

## Goals / Non-Goals

**Goals:** 真正透视3D、易观察落点的自由平台跑酷；移动碰撞与画面使用同一平台尺寸；教程、12关、皮肤与可保存试玩的编辑器形成闭环。

**Non-Goals:** 联网排行榜、账户系统、多人对战、自动跑道模式、复杂3D建模工具、已有游戏架构改写。

## Decisions

1. 复用本地 Three.js，esbuild 打包 `parkour/game.js` 到 `parkour/bundle.js`，保存许可证。不使用CDN；相较2D伪透视，可提供真实深度、镜头旋转和投影阴影。
2. `core.js` 负责固定小步物理、重力、起跳、缓冲跳、平台侧面/顶部/底部碰撞、存档点、金币和终点。渲染与输入不得改写物理规则。落脚高度以平台顶面 y 表达，人物身高由渲染引用物理尺寸。
3. `levels.js` 提供12个可达的预设路线：四种主题各三关。第一关宽平台、小缺口；后续增加平台数、转向、高差和较窄落点，使用存档点避免长距离重玩。城市车辆在路线下面的道路行驶，属于背景，不制造不可读的碰撞。
4. 相机默认在人物后上方，方向键及 WASD 的移动相对镜头；空格或画布单击跳跃；画布拖动转视角，不把拖动的释放误认为跳跃。键盘、触摸均清除失焦输入。触屏提供左摇杆、右跳跃按钮和画布镜头拖动；不用覆盖画面的手势移动。
5. `profile.js` 使用新键 `glow-parkour-v1`，与其他游戏分离。红色免费，橙黄绿青蓝紫黑粉棕深蓝深绿和彩虹每款2金币。同一局中金币领取一次，掉落复位不得重复领取；重新开始预设关卡可以重新赚金币。自创关卡金币仅供试玩，不增加商店余额，界面明确标注。
6. `editor.js` 使用带网格的俯视编辑面板，点击放置/选择平台，以表单修改顶面高度、宽深和位置；可放金币、设置起点、存档点和终点。最多80个平台，有限坐标和尺寸，验证起点/终点支撑，不宣称自动证明任意自创路线可达。保存到独立本地键 `glow-parkour-level-v1`，支持重新加载和3D试玩。
7. `scene.js` 保持一个WebGL渲染器，切换场景释放旧几何、纹理与材质；装饰合并或实例化，特效数量有上限，像素比最高1.5，阴影贴图1024。人物四肢随移动摆动、笑脸朝前，主页待机摆动且点击跳跃；不使用廉价贴图充当3D场景。
8. 游戏暂停、切后台或打开商店/编辑面板后，物理暂停，输入清空；加载失败或WebGL不可用显示原因与返回按钮，不留白屏。声音只在用户操作后启动，可静音，暂停同步暂停。

## Risks / Trade-offs

- [移动设备负载] → 简单材质、有限特效、合并静态物体、像素比上限、只在游玩/主页需要时绘制，检查资源切换不累积。
- [平台跳跃手感] → 物理与场景同尺寸，缓冲跳/短暂离台起跳容错，逐关验证可达，失败回到最近存档点。
- [自由镜头遮挡] → 场景树木放在路线外，跟随镜头靠近时避开平台实体；提供一键复位镜头。
- [本地存储不可用] → 本局保持可玩，购买/保存明确提示未持久化；损坏内容规范化或拒绝并提示。
- [自创关卡不可通关] → 编辑器提示不自动验证整条路线，允许即时试玩调整；金币仅练习，避免编辑器直接刷余额。

## Migration Plan

1. 独立分支完成规格、测试、代码和本地打包，不修改已有游戏资产。
2. 单元、真实WebGL浏览器、桌面/手机/平板、自创关卡存取与试玩通过后，审查差异。
3. 更新版本化目录脚本和新游戏资源；通过现有PR/主线部署链发布，检查两个域名的入口、文件版本和真实浏览器路径。
4. 如需回退仅 revert 本次新游戏提交，保留之前已上线游戏与存档。
