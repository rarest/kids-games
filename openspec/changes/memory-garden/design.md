## Context

采用远程main c736cd4为基线，原有13个游戏，Three.js固定0.186.1和esbuild已安装。其他工作树和用户修改不动。动机见proposal.md。用户已确认制作且此前要求自动实施，当前依确认规则直接实施，不重新索取相同方案批准。

## Goals / Non-Goals

**Goals:** 真实3D、完整200关和消费规则、可用的触屏大牌桌、一次性结算与礼包、克制特效和可保存牌局。

**Non-Goals:** 联网同步、现金充值、无限生成关卡、修改既有游戏逻辑、云端3D生成。

## Decisions

1. memory/core.js为纯规则，profile.js为本地钱包/存档，scene.js和models.js负责Three.js几何，audio.js负责本地WebAudio音频，game.js负责DOM与输入。沿用现有本地bundle，不增加生产依赖。
2. 200关用确定数量公式，只有第40关回退，不把后来每40关也自动重置。第200关398对。两张相同身份才配对，后期共享造型配合不同配色和实体编号确保身份清晰。
3. 牌局包含卡身份/翻开状态/匹配状态、阶段、剩余计时、用时、翻牌次数；保存整个牌局。查看、加牌、炸弹作为有效阶段的事务：先验证可用状态再消耗，立即持久化。一次性奖励由completedLevels收据防重复。
4. 开局5秒观察，牌宽随实际牌数对数递减，从约90px降至56px且不再缩小，第40关仅4张牌时恢复大牌；手机和平板保持同样的可点击像素尺寸。只改变镜头默认跨度和起始视野，不重排或缩放世界坐标、图案和碰撞；长牌桌首行贴近HUD下方，避免上半屏空白。拖动浏览大牌桌，总览太小时点牌定位并恢复可点击视野，第二次点选才翻牌；复位、方向键和转屏沿用当前牌数的尺寸。主页展示保持原镜头。顶部明确显示返回游戏厅链接，沿用pagehide暂停和存档。点击和拖动按8px阈值区分，不触发网页缩放或选择。
5. 卡背与卡体实例化，立体图案只构建可见范围，缓存共享几何/材质。5种主题每40关更换，花草用合并/实例化装饰，限制DPR和阴影图，只在牌状态/镜头变化时更新阴影；暂停不用累积帧时间补算。普通物体无持续粒子，配对光圈限0.7秒，低配/减少动态偏好下停用环境飘落。
6. 首次通关奖励100金币是代理为未指定参数采用的明确默认值，已向用户说明。八次查看是一次购买增加8个同种查看次数，不增加额外装备槽。初始2份加牌、1次查看和1000金币，不赠8次查看。
7. 移动端布局用100dvh，UI在牌桌外，按钮48px以上。无WebGL时显示清晰错误，不冒充3D；音频自动播放限制下等手势解锁，不调用远程音频。

## Risks / Trade-offs

[796张牌不可同屏清楚点击] → 默认缩小但下限56px，拖动/点总览定位，绘制可见范围，保留固定坐标。
[存档失败会丢钱包] → 写入异常显式提示；不静默报告已保存，数据校验过滤非法余额/物品/牌局。
[软件浏览器不代表手机GPU性能] → 保留实际draw calls/资源数观察，手机尺寸真实输入和200关压力测试。

## Migration Plan

仅新增记忆花园并接入目录，原游戏代码不变；发布走现有main webhook，需要完整项目门禁和公开站点核验。当前先完成本地可玩交付，发布时不执行远程手工覆盖或改部署脚本。
