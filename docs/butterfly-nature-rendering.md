# 蜜语花园：模型、自然场景与远行稳定性

本次保留玩法、64人房间、存档和平板触控布局，替换渲染资源与场景组织。模型和纹理均为项目内生成，没有新增联网素材或付费依赖。

## 调研与决定

基于现有Three.js r160，不升级引擎。使用[共享实例网格](https://threejs.org/docs/pages/InstancedMesh.html)绘制花草与树木，用[合并几何](https://threejs.org/manual/pages/optimize-lots-of-objects.html)控制蝴蝶和人物的绘制调用。遵循[阴影说明](https://threejs.org/manual/pages/shadows.html)，维持一个投射阴影的太阳；屋顶纤维不单独投影，低性能模式降低曲面分段但保留完整花和树。蝴蝶体节、足、棒状触角和卷曲口器参考[美国自然历史博物馆](https://www.amnh.org/exhibitions/butterflies/anatomy)与[澳大利亚博物馆](https://australian.museum/learn/animals/insects/moths-butterflies-and-skippers-order-lepidoptera/)的结构说明。资料核对日期2026-10-25。

未采用整套高分辨率外部写实资产：当前小型浏览器游戏需要保留离线包、体积与移动端预算。重点先修轮廓和完整植株，再增加曲面、表面组织与天空层次。实际成果为细化的自然风格3D，不描述为照片级写实。

## 具体变化

- 曲边蝶翼、合并蝶身、六足、复眼、触角；16皮肤共享几何缓存，向上合翅及树枝持物保持。
- 弯曲分层茅草屋顶、木梁；原半径2.18和缩放不变，新结构通过宽门射线检查。
- 追捕者服装、关节、靴子、脸部和网具细节，原肢体动画轴保持。
- 曲面花瓣、花粉和叶片，完整树冠，四种天空、云与日月；硬件设备可用预生成环境光，软件设备使用简化曲面。

## 植物突变根因与修复

旧版用流式花编号生成高度、朝向与配色，同坐标换id会变形；新版本使用世界坐标种子。树干和树冠原先独立96米循环搬移，现改为32米固定世界单元、7×7有界实例池，整树共享世界位置，雾后才回收外围槽位。近景草和小花按固定空间纹理淡出，停下后不会搬移。

独立复核另外发现条件分支消费随机数会让联机新房屋改变其他草的位置。现在每株植物预先取完整随机参数，再决定是否显示；真实1→64人新增房屋、两种画质126组比较均保持新屋外植被不变。

## 验收

主源92项规则/网络/存档检查通过；9项真实浏览器覆盖四地图、64间房、16皮肤、上合翅、门口净空和坐标稳定。4597次相邻地块保留树位置比较最大差值0，停下30次更新树矩阵不变。实际原生加速飞行约46米后，花瓣和树干矩阵保持不变。

首次软件渲染测试发现模型细节使帧耗时上升，已保留负结果并降低软件模式曲面分段、完整装饰植物密度与屋顶纤维数量；硬件模式保留细节。前后固定视口参数与实测在主源evidence/nature-report.json，不外推服务器软件渲染帧率为平板实机表现。

最终同视口软件渲染样本：旧版约190.6ms/帧、160次绘制；新版约203.1ms/帧、50次绘制，分辨率系数均0.45。新增天空和曲面保留后总帧耗时约增加6.6%，因此不宣称软件设备帧率提升或已达到流畅。真实GPU/PBR设备仍使用更精细版本。
