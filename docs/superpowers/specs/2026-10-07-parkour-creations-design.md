# 樱花跑酷自创关卡扩展

用户已经批准开始实施；最后补充要求只有一个“保存”操作，不展示保存方式选择。现有游戏名微光跑酷，樱花是其中主题，不另建游戏或改名。

## 交付规则

1. 编辑器提供全部清空（确认仅清当前草稿）、双击/手机连续双点删除平台。允许空草稿；删除附着金币/存档/道具和无支撑起终点，不偷偷恢复示例平台。有效起终点和支撑平台齐全才允许试玩/保存。
2. 取消平台80、金币160、存档点80的固定数量上限，不换成另一个个数上限；保留有限数字、合理物理尺寸及数据安全校验。坐标范围拓宽以支持长路线。验证1000平台及超过旧金币/存档上限的正常存档、恢复和实绘，不能截断。
3. 起点、终点、金币、存档点和加速/高跳工具均可放置。加速1.6倍/高跳1.5倍，持续8秒游戏时间，同类刷新不无限叠加；暂停冻结、掉落清除效果，保留本局已拿金币，重新开局可再收集。原12关物理与金币规则保持。
4. 一个保存按钮：每份新作品成为关卡列表里的自创路线一、二、三等，稳定唯一ID；可改名、编辑已存作品，不因新建/刷新/更新自动覆盖或删除旧作品。旧单槽路线自动迁移为第一份，原存储键保留。草稿、作品库、原金币和衣服存档隔离。写失败保留旧记录和内存编辑内容，不谎报成功。
5. 本机先保存，已登录的家庭账号自动备份到私有账号路线库；未登录照常可保存、玩，无登录门槛或保存方式弹窗。离线保存排队；连接恢复后重试。不同账号本机缓存隔离，注销/无效身份不沿用前账号；不静默将全部访客路线混入账号。用户在已登录状态保存当前作品，才将该作品保存到该账号。冲突保留两份，不静默覆盖；单路线CAS。账号被用户明确删除时清除云作品，与“不会自动删除”不矛盾。
6. 已保存自创路线可在正式关卡列表直接选玩。自创本局收集的金币只在实际通关时入现有外观商店余额，掉落不重复收集，完成重复调用不重复领奖，新的闯关可再领奖。未完成/未保存草稿试玩不发商店金币。原皮肤/衣服2金币价格和本机钱包保持，不新增跨账号钱包或公共排名。
7. 通关显示恭喜过关、三音庆祝与烟花；遵守静音、暂停、退出和减少动画设置，效果有限时长且无资源增长。
8. 明确“回到小火箭游戏厅”按钮：主页、暂停/完成、编辑器均可点，触控至少48px，不被覆盖；编辑器离开时保存可恢复草稿，已保存作品不丢。实际跳转index.html并加载目录。

## 模块与安全

- editor.js处理路线校验，route-library.js处理稳定多作品库和旧记录迁移；core.js处理真实道具物理，profile.js处理一次性通关入账。
- 云路线独立表parkour_routes(owner_user_id,id,revision,level,updated_at)，外键family_user ON DELETE CASCADE；不扩大学科学习codec或迁移003，不改三科进度。API使用现有家庭session和Origin检查，GET/PUT/DELETE /api/family/parkour/routes(/:id)。单次JSON最大8MiB是传输安全边界，不限制平台/道具个数；本机保存仍保留超出传输大小作品并明确备份失败，不截断。
- UI只消费单一保存动作；family-routes.js复用shared/family-client.js认证，cloud缓存与dirty队列按owner隔离。
- 复用Three instancing，移除超长数组spread的栈风险；不承诺超出设备内存的无穷对象。
- 不修改联机Rescue/Racing/Shooter运行时、数学/英语/语文业务。保护最新main并发改动。
